# solv-stripe

Stripe integration for **SOLV Languages** (live online French courses and coaching for English-speaking professionals) and **De Prof à Pro** (90-day online group coaching for independent French teachers). Both businesses sell online services to individuals in Europe, paid upfront or in monthly instalments.

Built with Node.js and Express following the plan generated by Stripe's implementation planner:

| Need | Stripe product | How it is used here |
| --- | --- | --- |
| Payments | Stripe-hosted Checkout | `POST /checkout` redirects to Checkout. One-time prices use payment mode and issue an invoice; instalment prices use subscription mode and are capped to N payments with a subscription schedule. |
| Invoicing | Hosted Invoice Page | `npm run invoice` creates and emails an invoice (or an instalment plan billed by invoice). Customers pay by card, SEPA Direct Debit or bank transfer. |
| Tax | Stripe Tax | Automatic VAT calculation on Checkout and invoices, VAT ID collection for business customers (reverse charge), product tax code `txcd_20060045` (Training Services - Live Virtual). |
| After-sales | Customer Portal | Customers download invoices and update their payment method; they cannot cancel an instalment plan themselves. |
| Fulfilment | Webhooks | Purchases are confirmed by webhook, never by the success page, so SEPA and bank transfer payments are handled correctly. |

## Project layout

```
src/
  catalog.js     the offers (products, prices, instalments, tax codes) – edit this
  checkout.js    builds Checkout Session parameters
  instalments.js wraps a subscription in a schedule that cancels after N payments
  invoices.js    send invoices and instalment plans by invoice
  webhooks.js    event handling and fulfilment
  server.js      Express app: catalogue page, /checkout, /success, /portal, /webhooks/stripe
  store.js       purchase log (data/purchases.jsonl); swap for your database or CRM
scripts/
  setup-catalog.js  create or update products and prices in Stripe (idempotent)
  setup-portal.js   create the Customer Portal configuration
  create-invoice.js CLI to send an invoice to a customer
test/               unit tests with a fake Stripe client (`npm test`)
```

## 1. Set up

```bash
cd solv-stripe
npm install
cp .env.example .env     # then paste your test keys into .env
```

`.env` is git-ignored. Never commit keys. The keys you shared in chat are test keys; rotate them in the Dashboard if they were ever exposed more widely.

Then, in the **test mode** Dashboard:

1. **Stripe Tax**: Settings > Tax. Set your head office address (Berlin), confirm the default product tax code (`Training Services - Live Virtual`) and add your **Germany** registration. Add **EU OSS (One Stop Shop)** once your B2C sales to other EU countries pass the €10,000 yearly threshold. If you are a *Kleinunternehmer* (§19 UStG) set `KLEINUNTERNEHMER=true` in `.env` instead: no VAT is calculated and invoices carry the §19 note.
2. **Payment methods**: Settings > Payment methods. Enable Cards, SEPA Direct Debit, Link, Apple Pay and Google Pay. Enable **Bank transfers** if you want invoices payable by transfer, then set `INVOICE_BANK_TRANSFER=true`.
3. **Branding**: Settings > Branding (logo and colour appear on Checkout, invoices and emails).
4. **Public details**: Settings > Business > Public details. Add your Terms of Service and Privacy URLs (needed for the terms checkbox in Checkout).
5. **Emails**: Settings > Emails. Turn on successful payment receipts and failed payment emails.
6. **Billing**: Settings > Billing > Subscriptions and emails. Keep Smart Retries on and enable reminder emails for unpaid invoices.

## 2. Create the catalogue

Edit amounts and names in `src/catalog.js` (the shipped prices are placeholders), then:

```bash
npm run setup:catalog   # creates products and prices, prints the price ids
npm run setup:portal    # creates the Customer Portal configuration, prints STRIPE_PORTAL_CONFIG_ID for .env
```

Running `setup:catalog` again is safe: unchanged prices are reused, changed amounts get a new price and the lookup key moves over.

## 3. Run locally

```bash
npm run stripe:listen   # in one terminal (needs the Stripe CLI); copy the whsec_... into .env
npm run dev             # in another terminal, then open http://localhost:4242
```

Test cards: `4242 4242 4242 4242` (success), `4000 0025 0000 3155` (3D Secure), `4000 0000 0000 9995` (declined). For SEPA use IBAN `DE89370400440532013000`. Full list: https://docs.stripe.com/testing.

What to try:

- Buy "Paiement en une fois": a payment-mode Checkout with VAT shown, then a receipt and invoice by email.
- Buy "3 mensualités": a subscription-mode Checkout. In the Dashboard the subscription now has a **schedule** ending after 3 payments. Use a **test clock** (Dashboard > Customers > Test clocks) to fast-forward and watch the invoices and the final cancellation.
- Enter a valid EU VAT ID from another country at Checkout: VAT becomes 0 (reverse charge).
- `npm run invoice -- --email you@example.com --price dpap_90d_upfront --country FR --line "1 rue X" --city Paris --postal 75001` sends an invoice; pay it from the hosted invoice page.
- `npm run invoice -- --email you@example.com --price dpap_90d_6x` creates six monthly invoices sent automatically.

## 4. Go live

1. Deploy the app (any Node host). Set `APP_URL` to its public URL and use **live** keys.
2. Dashboard > Developers > Webhooks: add `https://<your-app>/webhooks/stripe` with these events:
   `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `invoice.paid`, `invoice.payment_failed`, `customer.subscription.deleted`. Put the signing secret in `STRIPE_WEBHOOK_SECRET`.
3. Run `npm run setup:catalog -- --live` and `npm run setup:portal` against the live account.
4. Repeat the Dashboard settings from step 1 in live mode (Tax registrations, payment methods, branding).
5. Link the "Pay now" buttons on solvlanguages.com to `POST https://<your-app>/checkout` with the `lookup_key` field, or simply to `https://<your-app>/`.

## How instalments work

Checkout cannot cap a subscription to N cycles on its own. When the `checkout.session.completed` webhook arrives for an instalment purchase, `ensureInstalmentSchedule` creates a subscription schedule from the subscription with `iterations: N` and `end_behavior: "cancel"`. Stripe then bills monthly and cancels the subscription after the last payment. This is Stripe's documented pattern for instalment plans and needs no cron job. If a payment fails, Smart Retries and the failed payment emails take over, and `invoice.payment_failed` reaches the webhook so you can follow up.

## Notes for a German Freiberufler

- Prices are stored **VAT inclusive** (`tax_behavior: inclusive`), as consumer prices must be in the EU. Stripe Tax computes the VAT share per customer country.
- Stripe invoices are valid German invoices once your branding includes your name, address and tax number (Settings > Invoice template: add "Steuernummer: ..." or "USt-IdNr.: ..." to the footer).
- B2B customers (e.g. teachers buying De Prof à Pro through their own business) can enter a VAT ID at Checkout. For EU customers outside Germany this applies the reverse charge automatically.
- Stripe Tax threshold monitoring (Dashboard > Tax > Monitoring) warns you when you need to register for OSS or in another country.
- The `data/purchases.jsonl` log is a stop-gap. Export payments and invoices from the Dashboard for your accountant, or connect your bookkeeping tool from the Stripe App Marketplace.
